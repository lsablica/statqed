# Execution Plans

Execution plans are living, self-contained documents. A new agent should be able to continue from the repository without prior chat context.

Every active plan contains:

- purpose and observable outcomes;
- context and definitions;
- milestone dependency graph;
- task-by-task instructions;
- validation and acceptance criteria;
- Progress checklist with timestamps/commits;
- Surprises & Discoveries;
- Decision Log;
- Outcomes & Retrospective;
- recovery/idempotence notes.

Update these sections while working, not only at the end. Preserve history when revising direction. Tasks in `work/backlog.yaml` are the scheduling source of truth; plans explain why and how.
