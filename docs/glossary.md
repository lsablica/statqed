# Glossary

Status: **Draft**.

**Assurance artifact:** portable bundle recording claims, dependencies, evidence, certificates, provenance, and verifier locks.

**Assurance graph:** typed DAG whose edges state valid dependency relations among claims, assumptions, computations, data facts, diagnostics, attestations, and provenance.

**Certificate producer:** untrusted program that emits a candidate result and witness.

**Checker:** small deterministic program whose acceptance is linked by theorem to a precise proposition.

**Claim:** typed proposition intended to support a reportable conclusion.

**Data commitment:** recorded recomputation relation between an artifact and named bytes or a logical-data representation under exact algorithms. Digest-based substitution resistance remains conditional on named cryptographic assumptions and does not prove physical provenance.

**Diagnostic:** computed or observed non-deductive assurance input that may inform scientific judgment but does not establish a model assumption.

**Estimand:** target functional or quantity of scientific interest, distinct from estimator and fitted coefficient.

**Evidence object:** typed support whose interpretation states exactly which proposition, if any, it can support and under which verification mode. Attestations, diagnostics, citations, provenance, and unresolved obligations remain distinct assurance inputs with non-deductive or blocking roles.

**External assumption:** premise about the physical/scientific world that is not established merely by formal verification of code or data.

**Identification:** relation connecting a scientific estimand to observable-data quantities under assumptions.

**Method pack:** end-to-end package of semantics, theorems, witnesses, checkers, producers, frontends, tests, provenance, and citations.

**Probability context:** structured record of probability sources or interpretations, laws, random and fixed objects, conditioning, nesting/coupling, and quantifier scope. The exact public ontology is deferred to RFC-0004.

**Statement digest:** lookup/integrity digest over versioned canonical elaborated proposition bytes and their meaning-bearing environment. It is distinct from theorem identity, proof/build locks, source review, and proof body.

**Theorem lock:** the governed theorem identity plus canonical elaborated proposition/environment identity, independently authorized registry-record root/policy, proof/build lock, actual axiom report, and any checked compatibility path required by an artifact. Exact fields remain Draft under RFC-0005.
