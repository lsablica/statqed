# Documentation Map

## Normative direction

- `CHARTER.md` — mission, non-goals, constitutional separations.
- `ARCHITECTURE.md` — system decomposition and trust modes.
- `docs/design/` — accepted or proposed scientific design.
- `docs/spec/` — versioned machine-facing formats and semantics.
- `docs/adr/` — architectural decisions.
- `rfcs/` — debated constitutional changes.

## Execution

- `docs/exec-plans/` — living, self-contained implementation plans.
- `work/` — dependency ledger, task contracts, and status.
- `agents/` — canonical role/workflow/review contracts.

## Assurance

- `docs/quality/` — definition of done, test strategy, dashboard, trust reports.
- `source-audits/` — theorem and software-semantic lineage.
- `theorem-registry/` — stable theorem metadata and statement locks.

## Research

- `docs/research/` — benchmark, agent experiments, and publication programme.
- `docs/standards/` — external interoperability and primary-source map.

Documents label their maturity. A roadmap or plan is not an implementation specification unless it explicitly says so.
