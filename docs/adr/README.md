# Architecture Decision Records

ADRs record concrete architectural decisions after or alongside RFC discussion.

Statuses: Proposed, Accepted, Rejected, Superseded, Deprecated.

An ADR states context, decision, consequences, alternatives, validation, and supersession. SQ-0001 must either accept a provisional ADR or record its explicit blocker before implementation depends on it.

Accepted ADRs also record the acceptance date, exact reviewed commit or content-addressed surface, named independent reviewer roles, and linked review record. An architectural direction may be Accepted while a narrower implementation choice remains explicitly blocked by a Draft RFC; the ADR must state that limit and no implementation may treat the Draft choice as settled.
