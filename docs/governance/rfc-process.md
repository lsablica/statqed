# RFC Process

An RFC is required for core ontology, evidence taxonomy, normative encoding, theorem ID semantics, TCB, compatibility, public method-pack contract, or guarantee interpretation.

1. Open a Draft using `agents/templates/rfc.md`.
2. Assign statistical, formal, interoperability, and security reviewers as applicable.
3. Gather primary sources and prototypes.
4. Resolve examples, nonexamples, alternatives, and migration effects.
5. Keep implementation experimental until the RFC is Accepted.
6. Record dissent and decision rationale.
7. Update ADRs/specs/tasks atomically.

Accepted RFCs are immutable; corrections create a successor RFC. Emergency security changes require retrospective review.
