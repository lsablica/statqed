# Compatibility Policy

Status: **Draft; RFC required before Candidate artifacts**.

Compatibility is assessed separately for source API, IR, artifact bytes, theorem meaning, method packs, adapters, and verifier behavior.

A reader may accept an old artifact only under an archived verifier or an explicit migration. Theorem replacement requires equality of canonical elaborated proposition bytes in the same locked environment or a checked compatibility theorem over the complete propositions in the needed direction, with the path recorded in the new result. A statement digest or registry assertion alone is insufficient. Lossy migrations produce a new artifact and disclosure.

Deprecations name successor, rationale, earliest removal, and historical-verification path.
