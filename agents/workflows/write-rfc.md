# Workflow: Write and Resolve an RFC

Use for core ontology, trust, artifact, theorem-ID, compatibility, or public method-contract decisions.

1. Define the precise decision boundary.
2. Gather primary sources, standards, implementations, and conflicting variants.
3. Write examples, nonexamples, and failure cases before the proposed rule.
4. Compare at least two viable alternatives, including “defer.”
5. State formal, IR, artifact, frontend, trust, security, and migration effects.
6. Identify reversible versus irreversible choices.
7. Assign statistical, formal, interoperability, and security reviewers as applicable.
8. Record objections and resolution.
9. Mark Draft, Accepted, Rejected, Superseded, or Withdrawn.
10. Update ADRs, specs, plans, and task dependencies after acceptance.

No implementation may treat a Draft RFC as settled semantics.
