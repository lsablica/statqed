## Profile disposition

The reviewed profile is `statqed.cbor-core.v1`. It selects RFC 8949 core
deterministic encoding, including unsigned bytewise lexicographic ordering of
complete encoded map keys. It does not select the length-first compatibility
variant. Preferred integer and length heads and definite-length containers are
mandatory; strict verification rejects rather than repairs alternate bytes.

The accepted semantic subset is deliberately small: bounded direct CBOR
integers in `[-2^64, 2^64-1]`, byte strings, exact Unicode scalar strings,
ordered arrays, maps whose raw entries survive duplicate/order checks and whose
keys are integers or text, booleans, and null. Unicode is preserved exactly;
there is no normalization. The v1 profile rejects tags, floats, indefinite
forms, bignums, rationals, decimals, intervals, extensions, nonpreferred
heads, duplicate keys, and all unstated semantic coercions. Valid diagnostic
interval shapes use accepted-range integer endpoints only and remain
unsupported rather than becoming normative values.

The result taxonomy keeps CBOR well-formedness, validity, application
expectedness, deterministic-profile conformance, restricted CDDL shape,
semantic validity, schema validation, digest verification, resource limits,
and operational failures distinct. CDDL is structural evidence only.

Resource limits are fixed at 1 MiB input and output, 64 KiB text/byte strings,
1,024 array items or map entries, 4,096 total items, depth 32, and 4,096-byte
diagnostics. The diagnostic typed-JSON transport has a separate 2.2 MB cap.

## Implementation and differential evidence

Prototype A is an isolated Rust 1.97.1 crate below `schemas/prototypes/`; it
uses a project-owned ordered-entry decoder and only uses `minicbor` 2.3.0 for
preferred primitive/header emission. Prototype B is a standard-library-only
CPython oracle, written directly from the reviewed candidate and using a
project-owned parser/encoder. Neither implementation calls the other, consumes
the other's output as truth, or uses a shared canonicalization library.

The semantic catalogue was committed before final bytes. Its final 273 cases
contain 70 accepted and 203 rejected fixtures. Both implementations agree on
all accepted bytes and applicable semantic/result observations; 69 accepted
fixtures have retained binary goldens. The harness reports zero failures and
detects all 20 deliberately incorrect encoder/decoder mutations. Six minimized
historical failure records remain retained.

The final review cycle corrected a subtle distinction discovered by the
cryptographic reviewer: a fully present 129-byte identifier is a field-specific
identifier failure, whereas a missing or truncated length-prefixed component
is `digest.component_length`. Two semantic-first fixtures preserve that
boundary. A branch-wide diff review also removed three blank lines at EOF and
regenerated every affected content binding.

## Generic data-free digest framing

The Experimental frame has magic `StatQED-Digest\0`, then six ordered unsigned
32-bit big-endian length-prefixed components: purpose, algorithm, profile,
object-class/schema identifier, framing identifier, and payload. V1 fixes
`sha-256`, `statqed.cbor-core.v1`, and `statqed.digest-lp.v1`; identifiers are
ASCII, grammar-restricted, nonempty, and at most 128 bytes. The frame binds an
object-class/schema identifier but does not resolve or authorize it.

Mutations cover purpose/domain replay, algorithm/profile/schema/framing
substitution, unsupported fallback, downgrade, truncation, concatenation,
empty components, reorderings, payload changes, trailing input, allocation
bounds, and invalid identifiers. Digest equality remains conditional on
framing and SHA-256 assumptions. It does not prove collision absence,
provenance, logical-data identity, authorization, or statistical validity.
