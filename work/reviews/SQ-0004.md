## A. Rust/source currentness

APPROVE. Official primary sources were retrieved on 2026-08-09 and are
retained with exact locators in `backend/evidence/source-lock.json`. The source
reviewer independently confirmed both rustc/Cargo source identities, rustup
1.29.0 provenance, Cargo `rust-version` and resolver semantics, workspace lint
inheritance, platform tier boundaries, current advisories, RustSec inputs,
action commits, and licenses.

The review corrected three easy-to-overstate points before approval. Rust
1.85.0, not 1.85.1, stabilized Edition 2024; resolver 3 fallback is not MSRV
proof; and Cargo 1.85.1 predates current Cargo/tar, registry, and libssh2 fixes.
The final record therefore treats 1.85.1 only as the directly tested offline
floor, never as an acquisition, release, or current network-security tool.

Rust, Cargo, rustup, and cargo-audit use MIT OR Apache-2.0 licensing subject to
their third-party notices. The RustSec database is CC0-1.0 with explicitly
marked CC-BY-4.0 imports. Both project packages and both used GitHub Actions
are MIT.

## B. Workspace and MSRV reproduction

The workspace is deliberately limited to dependency-free `statqed-core` and a
thin `statqed-cli`. Both inherit Edition 2024, `rust-version = "1.85.1"`, the
MIT license, and workspace lints; every target also has
`#![forbid(unsafe_code)]`. The lock contains only those two local packages.

The independent workspace review ran formatting, Clippy, tests, and doc tests
under Rust 1.97.1 and repeated Clippy/tests/doc tests under Rust 1.85.1 with
`--locked --offline`. It found two non-blocking hardening gaps in the initial
candidate: error tests derived expected text from the implementation, and the
broken-output test did not assert `ExitCode::FAILURE`. Both were corrected
before `ed4404a`. Later API review required permanent 8,192/8,193-byte aggregate
limit cases; those pass under both pins.

`backend/tools/run_isolated_checks.py` generated the lock twice in independent
fresh current-Cargo homes and obtained byte-identical output. It acquired the
exact graph with Cargo 1.97.1, switched the development path offline, and ran a
separate 1.85.1 floor in a scrubbed offline environment. Its initial version
probes copied the ambient environment while the evidence claimed only
`RUSTUP_HOME` inheritance; security review blocked that claim. Commit
`ce0f42c` moved every identity probe into the same constructed isolated
environment and regenerated the bound transcript.

## C. API and deterministic error behavior

APPROVE. The conformance reviewer confirmed a clean reusable-core/process-I/O
boundary, protocol version 1, fixed response field order, stable symbolic
codes, stdout/stderr separation, exit 2 for malformed/unsupported input, exit
1 on broken output, and absence of timestamps, random IDs, rejected input,
locale text, host paths, stack traces, and dependency debug strings.

Permanent process and library tests cover no arguments, unknown command and
option, missing/empty/invalid/repeated values, structured-looking truncation,
unexpected arguments, non-UTF-8 Unix arguments, per-argument/count/aggregate
limits on both sides, deterministic randomized sequences, and broken output.
The accepted bounds are 64 arguments, 4,096 bytes per argument, and 8,192
aggregate bytes.

The reviewer initially blocked because the implementation enforced the
aggregate bound but permanent tests covered only the other two bounds while
documentation claimed all three. Commit `465e041` added exact 8,192-byte
boundary and 8,193-byte rejection cases at both library and process levels.
The reviewer then approved exact final implementation head `33d7a50`.

This protocol is only a bootstrap CLI surface. It is not an artifact-verifier
schema and introduces no statistical, encoding, archive, digest, registry,
certificate, or frontend semantics.

## D. Security and malformed-input review

APPROVE after three correction rounds. All 20 retained cases reject for the
intended reason: project unsafe code; removed forbid; workspace/package
rust-version changes; graph drift without lock update; changed lock bytes;
alternate project registry; ambient credentials; floor acquisition; timestamp,
random, and host-path output; panic and Debug output; floating Actions;
persisted checkout credentials; elevated top-level and quoted job permissions;
and workflow Cargo credential and alternate-registry environments.

The first workflow checker rejected only literal floating-action and checkout
credential mutations. Review demonstrated that valid inline YAML permission,
credential, and registry forms bypassed it. A first correction still accepted
extra `id-token: write` within the top-level permissions block and quoted job
keys. The final checker requires exactly one top-level permissions declaration
whose entire body is only `contents: read`, recognizes quoted permission keys,
and rejects credential/alternate-registry variable names anywhere in the
workflow. Independent direct variants and actionlint 1.7.12 pass.

The security reviewer also ran an independent 8,433-case CLI corpus over
exhaustive small grammars, exact resource boundaries, randomized bytes,
non-UTF-8, repeated/truncated input, and environment perturbations. Its
review-only digest is
`40929146f026043dcf67a95c468facea354173345dae9f3da6f9cc0b064343f7`.
No production `unsafe`, `unwrap`, `expect`, panic/unreachable macro, or
unchecked indexing path was found.

The advisory extractor rejects parent traversal, links, and special members
before extracting the two hash-verified task inputs into a fresh temporary
directory. It is not a generic bounded artifact extractor and must not be

## Remaining limitations

- Direct evidence covers only the named local Linux x86-64 host and observed
  hosted Ubuntu x86-64 image. Other platforms and targets are untested.
- RustSec is point-in-time and dependency-scoped; action pins and databases
  require monitored updates.
- A syscall-level no-network trace was unavailable because ptrace was denied.
  Offline flags, clean homes, absent-dependency failure, and credential/registry
  guards are the retained fail-closed evidence.
- The workflow checker is a narrow static guardrail bound to the exact workflow,
  not a general YAML or shell security verifier.
- Safe Rust does not remove compiler, standard-library, OS, dependency,
  resource, or supply-chain trust.
- No Draft RFC was accepted. No statistical validity, schema, canonical bytes,
  data identity, digest, artifact, theorem lock, registry, certificate,
  frontend, or verified-analysis claim was introduced.
